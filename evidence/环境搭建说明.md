# 受影响环境搭建步骤

```bash
# 1. 下载官方 3.2.3 release（受影响区间 3.0.0 – 3.2.3）
curl -sSL -o nacos-server-3.2.3.tar.gz \
  https://github.com/alibaba/nacos/releases/download/3.2.3/nacos-server-3.2.3.tar.gz
# sha256: 10cca4e92e78e5c57934890fe87e45888b46d7fd8c0532dc3b7161edd93c155e
tar xzf nacos-server-3.2.3.tar.gz && cd nacos

# 2. 首次启动的三个必填项（startup.sh 会交互式索取，预填以便非交互启动）
#    注意：这三项与漏洞无关，nacos.core.auth.enabled 保持出厂默认 false
SK=$(echo -n 'LabOnlyNacosTokenSecretKey0123456789abcdef' | base64 -w0)
sed -i "s|^nacos.core.auth.plugin.nacos.token.secret.key=$|nacos.core.auth.plugin.nacos.token.secret.key=${SK}|" conf/application.properties
sed -i "s|^nacos.core.auth.server.identity.key=$|nacos.core.auth.server.identity.key=serverIdentity|"           conf/application.properties
sed -i "s|^nacos.core.auth.server.identity.value=$|nacos.core.auth.server.identity.value=labsecret|"            conf/application.properties

# 3. 单机启动（内嵌 Derby）
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
bash bin/startup.sh -m standalone < /dev/null

# 4. 端口
#    8848  服务端口，contextPath /nacos  —— OPEN_API / ADMIN API
#    8080  控制台端口，contextPath /     —— Console API

# 5. 初始化管理员，并发布一份含敏感信息的生产配置（模拟真实环境）
curl -s -X POST 'http://127.0.0.1:8080/v3/auth/user/admin' -d 'password=Adm1n@LabPwd'
TK=$(curl -s -X POST 'http://127.0.0.1:8080/v3/auth/user/login' \
     -d 'username=nacos&password=Adm1n@LabPwd' | python3 -c 'import sys,json;print(json.load(sys.stdin)["accessToken"])')
curl -s -X POST 'http://127.0.0.1:8080/v3/console/cs/config' -H "Authorization: Bearer $TK" \
  --data-urlencode 'dataId=payment-service.yaml' --data-urlencode 'groupName=PROD' \
  --data-urlencode 'namespaceId=' --data-urlencode 'content=<含数据库/Redis 口令与 HMAC 密钥的 YAML>'
```

## 环境要点

- 鉴权开关**全部保持出厂默认**：`nacos.core.auth.enabled=false`、`admin.enabled=true`、`console.enabled=true`
- 权限缓存开启（`caching.enabled=true`），因此利用链中存在约 15s 的生效延迟
- 全程绑定 127.0.0.1，未对外暴露

## 执行 PoC

```bash
python3 poc/poc_nacos_unauth_admin.py -t http://127.0.0.1:8848 --no-proxy --cache-wait 20
# 退出码 0 = 漏洞存在且接管成功
```
